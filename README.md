# Hold Rep — 单杠 / 靠墙静蹲 自动计时、计数 PWA

纯 HTML/CSS/原生 JS，无构建、无 npm。姿态识别使用 MediaPipe BlazePose（模型与 wasm 已放在 `vendor/`），首次加载后完全离线可用。

## 目录
- `index.html` `css/app.css` `js/{config,detectors,db,app}.js` — 应用
- `js/config.js` — **所有识别阈值集中在这里**
- `manifest.webmanifest` `sw.js` `icons/` — PWA
- `vendor/mediapipe/` — MediaPipe Tasks Vision 脚本、wasm、BlazePose Full 模型（本地，约 22MB）
- `serve.py` — 本地静态服务器

## ⚠️ 重要：必须是 HTTPS
iOS Safari 只在 **HTTPS**（或 localhost）下允许调用摄像头、注册 Service Worker。iPhone 访问电脑的 `http://192.168.x.x` 不行。两种办法任选：

### 方案 A：免费静态托管（最省事）
把整个目录上传到 GitHub Pages / Cloudflare Pages / Netlify（拖拽即可，无需服务器、无需开发者账号）。得到 `https://…` 地址后按下面步骤安装。之后应用完全离线，托管站点可随时下线。

### 方案 B：局域网 + mkcert
```bash
brew install mkcert && mkcert -install
mkcert 192.168.x.x            # 换成电脑的局域网 IP，生成 *.pem
python3 serve.py 192.168.x.x.pem 192.168.x.x-key.pem
```
再把 mkcert 根证书（`mkcert -CAROOT` 下的 rootCA.pem）AirDrop 到 iPhone → 设置 › 通用 › VPN 与设备管理 安装 → 设置 › 通用 › 关于本机 › 证书信任设置 里启用完全信任。然后 iPhone Safari 打开 `https://192.168.x.x:8443`。

## iPhone 安装步骤
1. 在 iPhone **Safari** 打开应用 HTTPS 地址，首次进入训练页时按系统提示**允许摄像头**（被拒绝可到 设置 › Safari › 摄像头 改为「询问/允许」）。先进入一次训练页，让模型被缓存。
2. 点 Safari 底部「分享」按钮（方框带向上箭头）。
3. 菜单向下滑，选「添加到主屏幕」。
4. 确认名称为「Hold Rep」，点右上角「添加」。
5. 之后点主屏幕图标即可全屏启动，无网络也能用。

> 从主屏幕启动的 PWA 摄像头权限可能需要再允许一次，属 iOS 正常行为。

## 识别模型

使用 MediaPipe BlazePose，默认 **Heavy**（精度最高，约 30MB），「设置」页可切换为 **Full**（约 9MB，更快；手机发热或卡顿时用）。训练页右上角小标签显示模型、离地高度 ↑ 与单次推理耗时。除 2D 关键点外还使用 BlazePose 的 **3D 世界坐标**（判断前后摆动、屈髋、躯干后仰、身体扭转），以及耳朵（耸肩）、手指（正 / 反握）关键点。模型首次进入训练页时下载并缓存到独立缓存，之后离线可用，更新 App 版本不会重新下载。国内访问 github.io 可能较慢，请在 Wi-Fi 下耐心等待首次下载。

## 大字显示
类似 iOS 秒表：居中的超大细体数字（`mm:ss.cc`，毫秒位在两次识别之间插值，走得顺滑），画面压暗以便远距离看清。「设置」页「数字显示」或训练页右上角「Aa」可切换，默认开启，选择会被记住。

## 使用
手机竖屏放在单杠前方的地面或低处，稍微仰拍，前置摄像头拍到单杠和全身（Dead Hang 必须拍到双脚，用于判断离地；引体只需拍到上半身和单杠）。引体模式下屏幕上的白色虚线为估计的单杠高度（需先在起始位悬垂一下）。
- **Dead Hang**：手臂伸直、手腕高于肩、**双脚离地**、身体基本静止 → 自动计时；
  脚是否离地靠「地面校准」判断：进入训练页后先**双脚着地、双手放下站一下**（画面里需拍到脚踝或膝盖），之后**两只**脚踝都比各自站立位置高出 `HANG_FEET_LIFT`（默认 0.28 肩宽）才算离地，可区分「握杠踮脚」与「真正离地」。顶部提示条会告诉你当前状态。相机位置变动后，重新放下手站一下即可自动更新。不需要时可把 `HANG_REQUIRE_FEET_OFF_GROUND` 设为 false。
  姿势丢失 0.7s 以上自动暂停，回到悬垂接续。
- **Wall Sit（靠墙静蹲）**：手机竖放在正前方地面、拍到全身（至少髋和膝，最好含脚踝）。背贴墙蹲到大腿接近水平 → 自动计时；站起来超过 0.7s 自动暂停，蹲回去接续，与 Dead Hang 的计时规则完全相同（共用 `HANG_ENTER_MS` / `HANG_EXIT_MS` / `HANG_MIN_SEGMENT_MS`）。
  只在**大腿接近水平**时计时，蹲得太高（半蹲）或太低（深蹲）都不计，顶部提示条会提示「蹲得太高 / 蹲太低了」。正面仰拍时大腿朝向镜头被压缩、2D 膝角看起来仍接近伸直，所以用两项画面比例判断：「大腿 / 小腿」长度比 ≤ `WS_THIGH_SHIN`，且「膝盖低于髋的距离 / 躯干」在 `WS_DROP_MIN`～`WS_DROP_MAX` 之间（实测数据见 `config.js`）；侧面拍则看 2D 膝角（`WS_KNEE_ANGLE_MIN`～`WS_KNEE_ANGLE`）。训练页右上角「腿0.xx 膝0.xx」为这两项的当前值。
- **引体**：手臂基本伸直（起始位）→ 拉起到「下巴接近杠」或「手臂明显弯曲」→ 回到基本伸直 = 1 次（判定已放宽）。离开画面 2.5s / 离开起始位 9s 自动暂停，次数保留。两次间隔 >15s 自动分组。
- 结束本轮时会自动保存到历史（结果页「保存到历史」显示为已保存）；历史里可查看明细并删除（二次确认）。
- 报表：总览指标 + 近 7 / 30 天每日趋势（悬垂时长 / 静蹲时长 / 引体次数）。
- **备份**：记录存在主屏 App 自己的存储里（与 Safari 分开）。**删除主屏 App 会同时删除全部记录**，删除或重装前请在「设置 → 记录备份」导出 JSON（分享菜单选「存储到文件」），重装后再导入；重复导入会自动跳过已有记录。

## 动作分析报告

训练结束后，结果页（以及历史详情）显示「动作分析」，按教练常用的动作标准逐次 / 逐段评估：

- **总评分**（每次 / 每段 100 分，按问题扣分）+ 一句话总结 + 握法与握距。
- **首要改进**：出现次数 × 严重程度最高的问题，给出原因、训练口令和纠正练习。
- **其他问题**与**做得好的**。
- **每次 / 每段明细**：引体为拉起 / 顶停 / 下放时间、平均拉起速度（m/s）、评分、问题标签；悬垂为时长、肘角、晃动、评分。
- **训练安排**：按本轮最好成绩给出下次的组数 × 次数（或秒数）、速度控制建议、纠正练习和目标。

评估项：

| 引体向上 | Dead Hang |
|---|---|
| 底部是否伸直（肘角）、下巴是否过杠、拉起未到顶 | 手臂是否伸直 |
| 顶部耸肩（耳-肩距离，肩胛是否下沉） | 晃动（左右 + 前后，3D） |
| 伸脖子够杠（头部相对耳朵上仰） | 后段转为被动悬垂（逐渐耸肩） |
| 借力：屈髋 / 蹬腿 / 前后摆荡（3D） | 左右不对称（侧倾、一侧屈臂、扭转） |
| 节奏：拉起 / 顶停 / 下放（目标下放 2–3 秒） | 握距、正 / 反握、屈膝或直腿 |
| 左右不对称（到顶肘角差、侧倾、扭转） | 后段抖动（握力极限）、各段衰减 |
| 速度损失（VBT，后两次 vs 最快） | |

Wall Sit：下蹲深度（大腿是否到水平）、后段逐渐站高、身体不稳、重心偏一侧、后段抖动、各段衰减（阈值 `AN_WS_*`）。

阈值在 `js/config.js` 的 `AN_*`，规则与建议文案在 `js/report.js`。手机仰拍会让 3D 绝对角度有偏差，所以 3D 指标都看相对本人起始姿态的变化。正 / 反握判据若与实际相反，把 `AN_PALM_SIGN` 改为 -1。v25 之前的旧记录没有分析数据。

## 写入苹果健康

网页 / PWA 无法直接访问 HealthKit，所以借助 iOS「快捷指令」：结果页（或历史详情）点 **❤︎ 写入苹果健康**，App 会把本轮数据交给名为 **`HoldRep 写入健康`** 的快捷指令，由它在「健康」里记录一次体能训练。

传入的是 JSON 文本，例如 `{"seconds":85,"start":"2026-10-28 10:30:05","kcal":3.2}`：`seconds` 为本轮用时（秒），`start` 为开始时间（本地时间），`kcal` 为估算的活动能量（千卡，需在「设置」页填体重，未填为 0）。

热量估算：大卡 = (MET − 1) × 体重 × 小时。Dead Hang 悬挂时间按 MET 3.5，Wall Sit 静蹲时间按 MET 4.0，引体每次按 3 秒、MET 8.0，其余时间按 MET 1.3；参数在 `js/config.js` 的 `KCAL_*`。只是粗略估算。

**一次性设置：**「快捷指令」App → ＋，重命名为 `HoldRep 写入健康`（一字不差，中间有空格），依次添加：

1. **从输入中获取字典** — 输入：快捷指令输入
2. **获取字典值** — 键 `start`，字典选第 1 步的「字典」
3. **从输入中获取日期** — 输入：第 2 步的「字典值」
4. **获取字典值** — 键 `seconds`，字典选第 1 步的「字典」
5. **从输入中获取数字** — 输入：第 4 步的「字典值」
6. **获取字典值** — 键 `kcal`，字典选第 1 步的「字典」
7. **记录体能训练**（搜「体能训练」）：类型「功能性力量训练」；日期 = 第 3 步「日期」；持续时间 = 第 5 步「数字」，单位 **秒**；大卡 = 第 6 步「字典值」，单位千卡；**距离必须填值**，填 `0`（大卡、距离留空会报错）

注意（快捷指令的坑）：
- 新加的操作默认以**上一步的结果**为输入，第 2/4/6 步的「字典」务必手动改选第 1 步的「字典」。
- 取出的值都叫「字典值」，容易选错：点变量 → **重新命名**，分别改成 `start` / `seconds` / `kcal` 就清楚了。（在参数栏里直接点「字典」指定键的方式实测无效。）
- 测试：编辑页把「如果没有输入」设为「请求 文本」，点 ▶ 粘贴 `{"seconds":85,"start":"2026-10-28 09:00:00","kcal":3.2}`（复制粘贴，手打会变成中文引号）。可临时加「快速查看」检查「日期」是否解析出来。

训练结束后结果页会询问「写入苹果健康？」，点「写入」即跳转快捷指令；历史详情里也可随时点「❤︎ 写入苹果健康」补写。
第一次写入时 iOS 会请求「健康」权限，选允许。App 无法得知快捷指令是否成功，按钮只标记「已发送」；重复点击会重复写入。快捷指令运行完后从左上角返回 Hold Rep。

## 调参
改 `js/config.js` 后，运行 `./bump.sh` 刷新缓存版本。常见问题：
- 悬垂不计时 → 降低 `HANG_ANGLE_ENTER`、`HANG_WRIST_ABOVE`，或调大 `HANG_MAX_SWING_SPEED`
- 静蹲到位却不计时 → 看训练页「腿 / 膝」数值，按 `config.js` 里的实测表放宽 `WS_THIGH_SHIN` / `WS_DROP_MAX` / `WS_DROP_MIN`；太高或太低也计时 → 收紧
- 引体漏计 → 增大 `PULLUP_CHIN_MARGIN` 或增大 `PULLUP_TOP_ELBOW_ANGLE`；回落不算 → 降低 `PULLUP_START_ANGLE`
- 手机发热/卡顿 → 增大 `DETECT_INTERVAL_MS`，或 `SHOW_SKELETON:false`

发布前运行 `./bump.sh`（自动递增 `js/version.js` 的版本号并写入时间，`sw.js` 缓存名同步使用它），首页底部会显示「版本 · 更新于 · 缓存」，用来确认手机是否已是最新版。
